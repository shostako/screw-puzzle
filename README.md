# ネジ外し工房（試作）

スマホで流行っているねじ外しパズル（色合わせ型）の自作。最終目標は Android アプリ。

- 試作本体: `index.html`（Matter.js 0.19.0 を cdnjs から、poly-decomp 0.3.0 を jsDelivr から読み込む）と、キャラの画像 `assets/chara/`
- キャラの原画: `art/chara/`（ChatGPT で作った 1024×1536 の透過 PNG。`base.png` は最初の1枚で、ほかの表情を作るときの参照）。ゲームで読む軽い画像は `python3 scripts/prep_chara.py` が原画から作る
- 公開版: https://claude.ai/artifact/QhdRnGorN51nNAbN9JppKJ （同じ会話か、この URL を `url` に渡して再公開すると更新される）
- GitHub Pages: https://shostako.github.io/screw-puzzle/ （master への push で自動配信。中身は `scripts/build.sh` が包んだ `dist/index.html`）
- Android 版: Capacitor 8.5.2 で同じ `index.html` を包んだもの（`android/`）。下の「Android 版」を参照

## Android 版

2026-09-27 に作った（ユーザー要望「先に Android 化したい」）。

- アプリ ID `io.github.shostako.screwpuzzle`、名前「ネジ外し工房」、縦固定。minSdk 24、targetSdk / compileSdk 36
- `scripts/build_app.sh` が `www/` を作って `npx cap sync android` で `android/` へ写す。`index.html` が CDN から読む Matter.js と poly-decomp は `node_modules` から、丸ゴシック（M PLUS Rounded 1c の 700 と 800）は `@fontsource` から同梱するので、ネットにつながっていなくても遊べる。差し替え先が見つからない、外部の読み込みが残る、フォントのファイルが欠ける、のどれでも失敗する
- 端末のステータスバーとナビゲーションバーに重ならないよう、安全域のぶん body に余白を取る（Capacitor の SystemBars が入れる `--safe-area-inset-*`、無ければ `env()`）
- アイコンと起動画面は `python3 scripts/android_res.py` が `art/chara/face.png` から作る（アイコンはクリーム色の地に顔まわり、起動画面は木の色の地に胸から上）
- 振動のために `VIBRATE` 権限を足した
- ビルドに要るもの: Node 22、JDK 21、Android SDK（platform 36、build-tools 36.0.0）。新PC の WSL では `~/.local/opt/jdk-21` と `~/Android/Sdk` に入れてある（2026-09-27）
  ```
  export JAVA_HOME=~/.local/opt/jdk-21 ANDROID_HOME=~/Android/Sdk
  npm ci
  npm run app:apk      # → android/app/build/outputs/apk/debug/app-debug.apk
  ```
- スマホへの入れ方: USB でつないでいれば Windows 側の `adb.exe install -r`。つないでいなければ Google ドライブの `マイドライブ\screw-puzzle\` に置き、スマホのドライブから開いて入れる（初回は「提供元不明のアプリ」の許可が要る）
- 署名は今のところ、ビルドした PC のデバッグ鍵。別の PC や CI で作った APK は署名が違うので上書きでは入らない（入れ直すと端末に残した進み具合と自己ベストが消える）
- CI は PR ごとに Android のデバッグ APK まで組み立てる（Actions の成果物として 14 日残る）

## 現在のルール

- 上に色つきの箱が2つ。ねじをタップすると、同じ色で空きのある箱に入る。3本で満杯になると消え、次の箱が出る
- 合う箱が無いねじは待機スロット（5個）へ。新しい箱が出たら、スロットの同じ色のねじは自動で移る
- 板はすべて階層に属し、同じ階層の板は同じ色（離れていても）。上の階層の板に少しでも隠れているねじは外せない（タップすると震えて拒否）
- その時点の最上階層（ねじが残っている一番上の階層）から5段目までは、板とねじの色が見えて触れる。6段目は板の形だけ見え、ねじは色の無い影で触れない。7段目以降は板ごと見えない。最上階層の板が全部外れる（ねじ0本で落ち始める）と、見える範囲が1段下がり、新しく見えた板やねじの色はふわっと現れる
- 同じ階層の板どうしはぶつかる（回った板が隣の板に当たって止まる）。ねじ0本で落ちる板も、同じ階層でねじの残った板に当たれば引っかかって止まり、その下のねじを隠し続ける。ねじ0本の板どうしはすり抜ける（空中で弾き合わない）。違う階層どうしはすり抜ける
- 板を留めるねじが2本以上なら固定、1本になるとそのねじを軸にぶら下がり、0本で落下
- 全部の箱を埋めたらクリア。スロットが満杯で入れられるねじが無ければ詰み
- **ヒント**（2026-09-27）: 盤面の左上の電球。今の局面から解ける手順を探し、その最初の手のねじに金色の輪を5秒出す。揺れや落下の途中ならそれが収まれば外せる。解ける手順が見つからなければそう知らせる。使うとクリアの評価が下がる
- **クリアの評価**（2026-09-27、ユーザー指定「自力か、ヒントを使ったか、詰んで戻るを押したかで評価。時間が早いほど良い。ヒントと戻るは基本マイナス」）: ★3 から、ヒント1回ごと・戻る1回ごとに1つ減らし、遊んだ時間が目安（ねじの本数 × 4 秒）を超えたらもう1つ減らす。最低 ★1。時間はクリアや詰みの画面、設定や難しさ選びを開いている間は数えない。クリアの画面に星、時間と目安、ヒントと戻るの回数、ステージの自己ベスト（星が多い方、同じ星なら速い方。localStorage `screw-best`。ランダムは残さない）を出す
- **詰みから戻る**（2026-09-27、ユーザー要望「詰んだとき戻れるように。詰みルートの手前まで戻れるか」）: 詰みの画面の「解ける所まで戻る」で、解ける手順がまだ残っている一番新しい局面まで一気に戻る。戻したあと、分かれ目になった手（そこで外したために解けなくなったねじ）に赤い輪が4秒出る。何回でも使える。「最初から」は盤面をやり直す
- **ステージとランダム**（2026-09-27）: ステージはステージ番号から決まる固定の盤面。上部のサイコロからは、難しさ（やさしい＝ステージ3相当、ふつう＝8相当、むずかしい＝16相当）を選んで毎回ちがう盤面で遊べる。盤面には6桁の番号が付き、やり直しは同じ盤面。クリアすると次のランダムへ。ランダムで遊んでもステージの到達点は変わらず、「ステージに戻る」で続きに戻れる。解ける保証と難しさの条件はステージと同じ生成器を通る

## 見た目

市販アプリ（ユーザーが遊んでいるもの）のスクリーンショットを参考にしている（2026-09-27）。

- 背景は木目。起動時にノイズで描いて body の背景に貼る
- 箱は取っ手つきの工具箱。中に3つの穴を三角に並べる
- 板は半透明で彩度の高い色、太いクリーム色の縁取り。下の板やねじが透けて見える。外したねじ穴は白い輪で残る
- 板は盤面に対して大きい（2026-09-27 に形を 1.3〜1.55 倍へ拡大。ユーザー要望「参考画像の板は結構がっつり大きい。同じ階層の上の板を外すと下の板に当たって落ちきれず、隠れるねじが増えて難しくなる」）。同じ階層の板はすき間を詰めて隣り合わせに置く
- ねじは縁が濃い円に、立体風の十字。置いた時点では十字がほぼ正立する
- 上部は やり直しボタン／ステージ番号／外したねじの割合。盤面の右上に設定の歯車
- 画面の大きさへの合わせ方（2026-09-27、ユーザーの実機の感想「タブレットだけ反応が悪い。スマホとレイアウトがちょっと変わる」）: 盤面は置き場（`#stage`）に収まる最大の倍率で描く。スマホは幅で、タブレットは高さで決まる。上部の帯は盤面と同じ幅にし、ヒントと歯車は盤面の上の角に置く。上部の帯・ボタン・知らせ・カードは、画面（安全域を引いた `#app`）の大きさから決めた倍率 `--ui`（スマホ 1、大きなタブレットの縦向きで最大 1.8）で大きくする。倍率を置き場から決めないのは、倍率で上部の帯が高くなると置き場が縮み、行ったり来たりするため
  - 置き場の大きさは、ウィンドウの大きさが変わらなくても変わる（アプリで安全域の余白があとから効いたとき、フォントの読み込み）。以前は `resize` でしか収め直さなかったので、高さで決まるタブレットでは盤面が置き場から上へ約 20px はみ出し、上部のやり直しとサイコロに被さってタッチを奪っていた。`ResizeObserver` で置き場を見張って収め直す
- 丸い木のボタン（やり直し・サイコロ・ヒント・歯車）は、離した位置がボタンのまわり（外へ 24px まで）なら押したことにする。当たり判定は見た目の外へ約 6px。ブラウザ任せの click は押している間に指が 16px ほど動くと取り消され、親指を伸ばして上の隅を押すと「反応が悪い」ように感じた（2026-09-27、ユーザーの実機の感想）。盤面のねじは触れた瞬間に反応するので、差が目立っていた
- **演出**（2026-09-27、ユーザー指定）: 箱が満杯になると、フタが上から落ちて閉まり（白いチェック）、箱ごと外側の上へ回りながら飛んでいく。クリアすると下の両隅にクラッカーが出て弾け、紙吹雪が舞う。上のコインが光り、上がっていく4音のファンファーレが鳴り、「クリア」の文字が弾んで出る。紙吹雪はクリアの画面の上にも降る
- **設定**: 演出を「控えめ」と「派手め」から選ぶ（既定は派手め、localStorage `screw-fx`）。振動もこれに従う（2026-09-27 に組み替え。ユーザー指定「今の控えめは無し。派手めを控えめとし、さらに派手なものを派手めに」）
  - 控えめ（それまでの派手め）: クラッカー2発を時差で弾き、画面が一瞬光り、あとから上からも紙吹雪が降る。ファンファーレに和音とキラキラが重なる。箱が飛ぶときに風の音と星
  - 派手め: さらにクラッカーを両脇にも出して4発、1発目で盤面が揺れて虹色に光る。盤面から上のコインへコインが飛び（届くたびにチャリン）、空に花火が4発（ドン）。そのあと上から紙吹雪が約4秒降り続ける（2026-09-27 にリボンをやめて置き換えた。ユーザー指定「上の方に出る蛇みたいな曲線はやめて、その分紙吹雪を長く」）。音は太鼓の連打からシンバル、ファンファーレのあとにもうひと節。「クリア」の文字は回りながら大きく弾んで光る。箱はフタが閉まるとひと跳ねして紙吹雪をひとつかみ撒き、星の尾を引いて回りながら飛んでいく。クリアの画面はこの演出が一通り済むまで少し遅れて出る（1.75 秒）
  - 端末が「動きを減らす」設定なら、揺れ・光・花火は出さず、紙吹雪も少なくする
  - 紙吹雪は画面全体に重ねた透明なキャンバス（`#fx`、`position: fixed`）に描く。揺れる `#stage` の外に置いている（変形する親の中だと画面に固定されない）
  - 音はどれもその場で合成する（音声ファイルは使わない。Android 化のときに差し替える前提）
- **キャラ**（2026-09-27、ユーザー指定「ずんだもんのような子を、ねじの色に合わせてカラフルに、ピエロっぽい衣装で」）: 緑の髪のツインテール（毛先はピンクと青）、ねじの色の道化服、ねじ回しを持つ
  - クリアの画面ではカードの上に立つ。★3 はクラッカーで大喜び（派手めなら3回跳ねる）、★2 はウインクして親指、★1 は頭をかいて照れ笑い。詰みの画面では座り込んで涙
  - ヒントと戻るの知らせでは、左端に丸い顔を出す（ヒントは電球でひらめいた顔、戻ると解ける手順が見つからないときは照れ笑い）。知らせはヒントと設定のボタンより前に出るが、押した指はそのまま下のボタンに届く
  - 遊んでいる間は、箱の列の右（設定の歯車の下）に立つ（2026-09-27、ユーザー要望「ゲーム中も背景のどこかに表情を変えながら動きを付けたい」）。板より奥に描くので、揺れた板が重なれば板が手前になる。ふだんは最初の1枚の立ち絵で小さく揺れる。待機スロットが4つ埋まると焦り顔（冷や汗で身をすくめて小刻みに震える）、5つで座り込んで涙（揺れが小さくなる）。ねじを外すと小さく、板が落ちる手は大きく跳ねる。箱が埋まるとウインクして跳ね、ヒントを押すとひらめき顔、戻るや手順が見つからないときは照れ笑いをしばらく見せる。クリアでクラッカー（何度か跳ねる）、詰みで涙。表情が変わるたびにぽんと出る。盤面を読み込むと、やる気顔でひと跳ねして出てくる
  - 難しさ選びのボタンの左に丸い顔（やさしい＝笑顔、ふつう＝ウインク、むずかしい＝やる気顔）
  - 衣装のボタンがゲームのねじとそっくりなので、盤面の上には出さない
  - 画像を読めなかったとき（`index.html` だけを開いたときなど）はキャラを出さず、ほかはそのまま動く
  - Pages 版はホーム画面に置いたときの印も胸から上の絵（`icon-192.png`、`icon-180.png`）

## 実装メモ

- ステージはステージ番号を種にした乱数で自動生成（同じ番号なら同じ盤面）。ねじはステージ1で45本前後、以降 42〜72 本。板の形は7種類（棒、円弧〜C字、扇、しずく、円をつないだ塊、くの字、角の丸い3〜6角形）で、どれも符号付き距離関数で定義し、1.3〜1.55 倍に相似拡大して使う（`PLATE_SCALE`）
- ねじ穴は板を置く位置を決めてから選ぶ（`chooseHoles`）。板の縁から 20 以上内側の格子点のうち、盤面のほかのねじ穴から中心間 34 以上離れた点を、互いにできるだけ離して形ごとの数（2〜4）まで取る。1つ目は形の中心から一番遠い点なので、穴は板の端から埋まる。穴の位置を形に固定していたころは、大きな板を混んだ盤面に置こうとすると、ほぼどの位置でも既存のねじ穴とぶつかって段数が7段前後で止まった
- 板を下の階層から置く。階層の段数はステージ1〜3で7段、4〜6で8段、7以降9段を目標にする（2026-09-27、ユーザー要望「全ステージ階層を増やす、ある程度の難度が欲しい」。ねじ60本前後で盤面が埋まるので10段以上は入りにくい）。階層ごとに枚数（ステージ1〜3は2枚、4以降は2〜3枚）を先に決め、形と位置を変えて最大14回まで粘って埋める。1枚しか入らなかった階層は取り消す。1枚の板のねじ穴は最大4、ねじは最大75本。3段続けて1枚も入らなければその盤面は打ち止めにし、目標の段数に届かなければ種を変えて最大8回作り直す。同じ階層の板どうしは重ねず、すき間を 6 以上空ける。2枚目以降は先に置いた板のすぐ隣を狙い、置ける位置のうちすき間が一番小さいもの（18 以下が見つかればそこ）を選ぶ（`SNUG`）。下の階層の板とは面積の 15〜90% が重なること、下のねじを隠しすぎないこと（ステージに応じて最大 3〜6 本）を条件にする。重なりと同じ階層のすき間は、置いた板を 4px の格子に焼いておいて引く（`stamp`）
- ねじの色は10色（緑・水色・桃・黄・橙・赤・紫・銀・青・茶）を用意し、ステージ1〜3で5色、3ステージごとに1色増やして13以降は9色使う（2026-09-27、ユーザー要望「易しすぎる、色を増やそう」）。以前は3色から6色までで、単純な自動プレイでも全ステージクリアできた
- **解けることの保証と難しさ**（2026-09-27）: 色を割り当てたら、見えていて外せるねじ全部（階層は問わない）を手の候補として `solveFull` で手順を探索し、待機スロット（5）があふれずに全部の箱が埋まる手順があるものだけ採用する。さらにステージ2以降は「上から順に外すだけ（`solveOrder`）では解けない」、ステージ5以降は「手なり（合う箱に入れ、無ければ見えている中で一番多い色を待機、`greedyPlay`）でも解けない」割り当てだけを採用する。30回試して見つからなければ、解けるだけの割り当てか、最後は混ぜない割り当て（必ず解ける）に落とす
  - 板の動きは安全側に見積もる（`buildModel`）。前提は「揺れや落下が落ち着いてから次のねじを外す」（2026-09-27、板の拡大と落下の引っかかりに合わせて作り直した）
    - ねじ2本以上の板は動かないので、置いた位置の形で隠す
    - 1本留めの板は、重心が真下へ向かう短い向きに回る。回る途中を 10px 刻みの姿勢で調べ、同じ階層でねじ2本以上の板（動かない）に最初に当たる姿勢か、当たらなければ真下に垂れた姿勢で止まるとみなし、その姿勢（前後1刻みの余裕つき）で隠す。同じ階層にぶら下がっている板や引っかかった板があって押し合いうるとき、重心が支点のほぼ真上のとき（倒れる向きが決まらない）は、残ったねじを中心に板が届く円の中をすべて隠す。一度押し合いうる状態になった板は、その後も円で隠す（`wild`）
    - ねじ0本の板は、止まっていた姿勢からまっすぐ下へ落ちる。その途中に同じ階層でねじの残った板があれば引っかかったとみなし（`hungTop`）、落ち始めた高さより下のねじを盤面の幅いっぱい隠す。乗った先から滑り落ちて別の板に乗り移ることもあるので、たどりうる板（`catchers`）のねじが全部外れるまで引っかかったままとする。大きな板ではたどりうる板は同じ階層の板全部になり（ステージ1〜40の822枚すべて）、ねじ0本どうしはぶつからないので、同じ階層のねじが全部外れれば乗る相手は物理的に残らない。途中に何も無ければ落ちきって何も隠さない
    - 以前（〜2026-09-27）は、1本留めの板は常に届く円で隠し、ねじ0本の板は何にも当たらず落ちる（`collisionFilter.mask = 0`）ようにしていた。板を大きくすると届く円が盤面のほぼ全域になり、探索が打ち切りだらけになった
  - 探索（`solveFull`）は、残り3本以上の板のねじを合う箱へ入れる手を分岐させずに先に打つ。板が動かず隠し方も変わらないので損をしない手で、入れ替えても同じ局面になる手順を何通りも調べずに済む
  - 同じ色の箱が2つ開いているときは、多く入っている方へ入れる（ゲームの `openBoxFor`、探索の `openFor`、`solveOrder` で同じ規則）。以前はゲームと探索で入れる箱が違い、箱の満杯になる時期がずれて、探索どおりに外しても待機スロットがあふれることがあった
  - 詰みの判定は、落ちていく板が盤面の下へ抜けるか引っかかって止まり、ぶら下がった板の揺れもほぼ止まってから行う（`settled`。角速度 0.001 rad/ステップ未満、ねじ0本の板は速さ 0.04 未満）。0.003 では振れ幅4度ほどの揺れを止まったとみなし、揺れる板の端がねじを覆ったり外したりした。ただし、待機スロットが満杯で、合う箱のあるねじがどれも動かない板（ねじ2本以上）に隠れているときは、揺れを待たずに詰みにする（`hopeless`。動かない板はねじを外さない限り動かないので、状態は変わらない）。入れられるねじをぶら下がった板が覆っているときは揺れが収まるまで待つ。大きな板は揺れが収まるまで6〜7秒かかり、詰みの画面まで最後の手から9秒近く待たせていた（ユーザー指摘「ランダムで詰み判定が効かない？」、2026-09-27）。そこで、打つ手が無い間だけ、ぶら下がった板の速さに1ステップごとに 0.93 を掛けて揺れを早く収める（`calmStep`。止まる位置は変わらない。手が出れば外れる）。隣の板に寄りかかってずり落ちていく板はそれでも止まるまで長いので、打つ手が無い状態が2秒続き、速く動く板も無ければ（ぶら下がった板の角速度 0.004 未満、ねじ0本の板は盤面の下か、速さ 0.5 未満かつ角速度 0.004 未満）、止まりきるのを待たずに詰みにする（`CALM_WAIT`、`slow`）。ずり落ちがあとでねじを見せることがあれば早すぎる詰みになるが、手持ちの計測（ランダム12盤面）では待っている間に手が出たことは無く、万一のときも「解ける所まで戻る」で救える。最後の手から詰みの画面までは1〜5秒
  - 検証（2026-09-27）: 探索が返した手順を実際のゲーム（物理あり）で、毎手、盤面が 0.8 秒続けて落ち着くのを待ってから画面タップでなぞると、ステージ 1,2,4,5,6,7,8,10,13,14,16,20,25,30,40 の15ステージすべてクリア。落ち着いたのに外せなかった手0、拒否されたタップ0。落ち着くのを待たず、外せるようになった瞬間にタップしても、ステージ 3,9,15,21,27 の5ステージすべてクリア（こちらは保証の外）。手なりの自動プレイ（実際のゲーム、ステージ 3,5,8,10,13,16,20,25）は、板を大きくする前は8つ中3つクリア、今は1つ
  - 生成時間はデスクトップで平均 120〜140ms、最大 360ms 前後（ステージ1〜60）。以前は平均 70ms。割り当ての試行は平均 3 回前後で、ステージ1〜60はすべて「上から順に外すだけでは解けない」（5以降は「手なりでも解けない」）割り当てが見つかる
- 描画用の輪郭は距離関数からマーチングスクエアで取り出した多角形（Path2D）。衝突用には外周を粗く間引いて poly-decomp で凸な部品に分け、複合剛体にする。質量・重心・慣性モーメントは同じ格子から計算した実形状の値に置き直す（`Body.setCentre`）。慣性モーメントは Matter.js の既定に合わせて4倍
- 衝突の組み合わせは collisionFilter の category と mask を階層ごとに2ビット使って決める。下のビットはねじの残った板、上のビットはねじ0本の板。同じ階層でも、ねじ0本どうしはぶつからない
- 「隠れている」の判定は、上の階層の板の距離関数をねじの中心と外周16点（半径 SR+1）で評価する
- 板が1本留めになったとき、重心が残ったねじのほぼ真上（倒立の釣り合い）なら、左右どちらかへ回転速度 0.24 rad/秒 を下支えして押し出す。0.3 rad 傾いたら押すのをやめて重力に任せる。重心が少しでもずれていればその向き、ぴったりなら向きはランダム（2026-09-27、ユーザー要望「釣り合っていても徐々に傾いてひっくり返る」）
- **戻る**の仕組み: ねじを外すたびに、外す直前の板の状態（位置、角度、速さ、固定か、支点、押し出し中か）を記録する（`hist`）。戻すときは、ねじと箱を最初の並びから記録の手順どおりに動きなしで入れ直し（`rewindTo`、`settleNow`）、板は記録した状態に置き直す。戻る先は、途中の局面から `solveFull` で手順を探して決める（`rewindPoint`）。最初の局面は生成のときに解けると確かめてあり、詰んだ局面は解けないとみなして、その間を二分探索する（1回ずつ画面に返すので、探している間も画面は止まらない）。見積もりは安全側なので、戻る先は「確実に解ける局面」で、本当の分かれ目より手前になることがある
- 到達ステージは localStorage に保存
- `scripts/build.sh` は `dist/` に `assets/` も写し、ページが名前で読む画像（`CHARA` の表とアイコン）がそろっていなければ失敗する。Artifact へ公開するときは `assets/chara/*.webp` を `files` で一緒に上げる
